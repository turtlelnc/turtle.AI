# 因果性与 KV cache 数值检查

2026-10-07 对实际模型实现进行逐 Token 数值对照，使用随机小模型和已有的
2000 步 Wikipedia 检查点。环境为 MLX 0.31.2、Linux CPU、GCC 14.2，种子 7。
详细结果见 [JSON 记录](kv_causality_2026-10-07.json)。

## 发现和修复

1. **容量 MoE 的缓存计数重置。** 完整前向会按序列累计每个专家的分派次数，
   超过容量后丢弃对应分支；原缓存解码每次只处理一个 Token，重新计算容量和
   分派计数，导致两种路径的实际计算不同。现在每个 wide block 和每个循环层
   分别保存累计计数，采用与完整前向相同的容量与顺序。
2. **稀疏注意力并列分数。** 默认完整前向保留第 k 大分数的所有并列项，原解码
   却只取 k 项。默认解码现使用相同阈值规则。可选 gather 路径改为统一的 exact-k
   规则：并列时优先更早的键；packed/单序列/缓存使用相同选择，乘积累加用 FP32。
3. **SDPA 精度路径。** 开启 `--fast-decode-sdpa` 时，原先只有解码使用 SDPA，
   完整前向仍逐步计算 FP16 scores/probabilities。现在该开关同时作用于滑动
   注意力的完整前向和解码，保证对照使用相同计算路径。
4. **滚动上下文的历史状态。** 只删除旧 KV 会保留受已淘汰前缀影响的隐层状态，
   且位置和专家计数没有按滚动窗口重置。达到上下文边界后，现回退为保留窗口的
   完整前向，与 `--kv-cache 0` 对齐。复用 cache 时更改上下文长度会明确报错，
   要求先重置 cache。

默认完整前向的计算保持兼容；旧检查点可加载。启用可选 gather/SDPA 的完整
前向计算也在本次统一，因此这些开关可能改变旧版本的训练或验证数值。

## 实测结果

下表是混合与重复 Token 序列的完整前向/逐 Token 缓存解码最大绝对 logit 误差：

| 模型与输入 | 修复前 | 修复后，默认配置 |
|---|---:|---:|
| 随机小模型，混合 Token | 0.027344 | 0 |
| 随机小模型，重复 Token | 0.034790 | 0 |
| 2000 步模型，混合 Token | 4.928711 | 0 |
| 2000 步模型，重复 Token | 3.201172 | 0 |

修复后还验证了：改变后半段 Token 不影响前半段预测；滑动窗口边界；上下文淘汰；
全部稀疏分数相等但 V 不同；packed 与单序列结果一致；修改另一条 packed 序列
不影响第一条。上述默认配置样本的最大误差均为 0。

加速组合（SDPA、sparse gather、拆分 QKV、普通 RMSNorm）也通过；2000 步模型
最大绝对误差为 0.00390625。判断逐元素使用固定容差：

```text
abs(actual - reference) <= 0.002 + 0.001 * abs(reference)
```

这不是所有设备、模型或输入上完全等价的证明。检查覆盖两个模型配置和一个
种子，尚未运行 Metal。默认完整前向在原 256 个留出窗口上复测交叉熵仍为
3.5895349244，困惑度为 36.2172；检查点 SHA-256 未变。没有在此次重新训练模型。

## 回归与复现

新增 `mlx-model-checks` 直接使用 `main.cpp` 中的实际模型定义，避免复制一份
可能与运行时偏离的实现。CMake/CTest 自动执行随机模型的默认和加速两组数值回归；
原训练烟雾测试也覆盖加速配置的 packed 和梯度累积路径。共 4 项 CTest 均通过，
根目录 CPU 回归和分词器/数据测试通过。

```sh
cmake --build build-mlx --parallel 2
ctest --test-dir build-mlx --output-on-failure
./build-mlx/mlx-model-checks build-mlx/wiki-continued/model.ckpt
./build-mlx/mlx-model-checks build-mlx/wiki-continued/model.ckpt \
  --fast-sdpa --gather-sparse --split-qkv --generic-rms
```

测试程序固定使用 CPU，`CHECKS` 行输出 JSON。任一比较超出容差，程序返回非零。
本地原始日志和留出集复测结果在 `build-mlx/numerical-checks/`。

## 性能与下一步

达到滚动上下文边界后回退完整前向，意味着不能继续享受增量缓存的速度收益。
默认稀疏解码保留所有阈值并列键，也使用与完整前向相同的归约路径。后续性能
优化要在这些数值回归约束下进行，另需在 Apple Silicon 上验证加速内核。

下一步优先统计真实隐层的专家分派、容量丢弃率，随后补齐 RNG/学习率计划的
恢复状态，再投入更长训练与生成质量评估。
